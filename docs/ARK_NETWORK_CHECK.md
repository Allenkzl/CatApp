# 云容器到方舟的只读网络检查

用户确认在fix/cloud-ark-connectivity补充自检，用于定位本机35.4秒生成成功、云端600秒无响应头的差异。本轮不发起新的付费绘图。

## 范围

空间设置Seedream区“方舟网络自检（不绘图）”通过POST `/api/drawing/network-check` 触发后台检查。调用方只能提交空JSON对象，不接受目标URL、请求方法、代理、密钥或其他参数。受现有登录/同源规则保护；同一进程并发共享一次检查，完成后60秒内复用缓存。

探测固定Ark官方主机：DNS lookup；用服务器当前保存密钥GET模型目录，分别默认地址选择和强制IPv4；不带密钥HEAD图片API路由，若DNS含IPv6则追加IPv6 HEAD。均不提交图片生成请求，不跟随重定向，TLS正常校验，每项网络请求10秒截止，DNS3秒截止，响应2MiB上限。

结果只包含阶段耗时、状态码、允许列表错误码、请求ID、模型目录计数/指定模型是否列出、运行时版本。代理环境变量仅显示是否存在，不显示URL或凭据。原始响应体、请求头及密钥不返回。HEAD返回404/401属于方法/鉴权路由结果，不能据此判断绘图是否可用；GET目录200也不能证明大图POST或绘图可用。

同时给真实绘图传输的失败记录加入DNS/TCP/TLS、请求写出完成、已写字节及缓冲字节信息。请求写出完成只代表客户端已把数据写出，不证明服务商已接收或处理。此记录只在用户原有手动绘图发生时收集，不触发额外请求。

## 发布与判断

健康标识 `arkNetworkCheckVersion:1`；部署后从正式站POST空对象取得实际云容器报告。默认超时而IPv4成功时，优先检查地址族/路由；两者401/403时查凭据/策略；TLS失败查证书/出口；若GET目录和HEAD均快速响应，说明基础小请求通路正常，仍需排查实际大请求的上传或服务端处理。

代码测试和页面验证均使用本地模拟服务，无付费模型调用。按此前用户授权验证通过后合并/推送，再执行正式站自检。不能用本机探测结果代替云容器结果。
