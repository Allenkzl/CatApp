# 每日猫咪总结

## 当前行为

每日模式替代“每 N 张组一篇”，同一摄像头、同一北京时间日期只创建一篇正式总结。默认次日北京时间 00:10 创建任务，按排队进度编写英文故事再绘图；00:10 是入队时间，不保证此刻绘图已完成。单台摄像头可能拍到不同猫，当前没有个体识别，因此不得宣称整天跟踪的是同一只猫。

空间设置可修改次日生成时间 HH:mm 和目标篇幅6–8格，默认8格。素材不足时少画，没有照片不创建空作品。日期统一为 Asia/Shanghai，与服务器系统时区无关。

每日任务保存 `allPhotoIds`（该次截止时的全部观测）、`sourceCount`、`photoIds`（发送模型的代表照片）、目标格数和计划时间。相同内容哈希先去重，再根据时间跨度选最多18张代表照片（保留首尾），交给DeepSeek从中挑选可观察的不同活动并组织时间章节。采样不等于覆盖全天，也不保证自动识别模糊或相似画面；无记录时段视为未知。英文叙事和对白为创作，观察事实与不确定性单独记录。

每日绘图使用1920×2560纵向页面、两列6–8格，保持原有温暖水彩风格和全英文文字；实际调用、画质和模型权限仍需正式站生成验收。本地使用模拟供应商响应验证了8格故事→绘图→PNG入库，不以模拟图冒充真实成品。

## 今日预览

工作台、作品库、空间设置的预览按钮使用页面当前选择的日期，返回只读的素材数量、时间范围、候选照片和预计格数。该按钮不调用DeepSeek/Seedream，不产生API费用，也不创建正式作品；它是素材预览，不是AI漫画预生成。页面上明确说明这一点。

接口：`POST /api/daily/preview`，JSON `{ "date": "2026-10-27" }`，可选 `cameraId`。沿用网站管理访问和同源限制。日期无效返回400。

## 升级与重复生成保护

1. 发布前备份整个持久化目录，保留当前镜像版本。
2. 新版先迁移暂停旧三张组图，再初始化每日worker，网站自动生成开关默认开启。旧`CAT_AUTO_GENERATE=false`不再禁用每日模式；如需暂停，在网站空间设置保存关闭状态（基础设施验收先用无密钥独立目录）。不要在旧版开启环境开关触发旧批次批量付费。
3. 首次迁移以启用当天的北京时间日期为起点。未完成的旧批次标为 `legacy_paused`，保留照片、故事和历史状态；已完成作品保持可查看。旧批次在作品库中隐藏，不允许通过“重试”重新激活。
4. 当天照片（包括旧批次引用过的照片）进入该日总结；启用前的历史日期不自动回填，避免一次上线产生大量付费任务。
5. 每个摄像头/日期使用固定作品ID。重启、晚到照片或改生成时间都不自动重新绘图；晚到照片继续入库，在预览中可见，但不会被悄悄加入已冻结的任务。当前不提供自动修订成品。
6. 后台在运行时每2秒检查日程，服务停机跨过00:10后，恢复时补建启用日起尚未建立的任务；没有独立cron，也不保证服务器停机时仍能运行。
7. 生成请求中断按原规则进入失败状态，避免重复扣费；只有显式重试才重新处理。

## 为什么云端此前不生成

现场看到22张照片和7个 `ready_for_generation` 批次，两套密钥均configured，全部没有story/attempt/error记录。表现与自动worker关闭一致；仓库Compose模板缺省 `CAT_AUTO_GENERATE=false`。没有服务器操作入口，无法读取线上实际环境变量，因此该原因是有依据的诊断，尚非运行环境确认。

新版 `/api/capture` 的 `automation.workerEnabled`、`workerSource` 和 `workerBlockedReason` 暴露实际开关状态（不含密钥）；每日模式的控制来源为`website_setting`，关闭原因为`website_setting_disabled`。

2026-10-28起，每日模式改为网站持久化开关。首次升级补齐 `settings.autoGenerateEnabled=true`；已有布尔false会保留。网站设置优先于旧环境变量，无需运维逐次修改变量或重新创建容器。通过同源 `POST /api/settings` 可单独发送 `{"autoGenerateEnabled":false}` 或true，保存后下一次任务轮询即生效，重启后保留；同一接口也可保存生成时间和篇幅。参数必须是JSON布尔值，保存失败会回滚状态。

关闭不会取消已发出的付费请求（避免丢失返回结果）；当前请求完成保存后，下一阶段和其他任务暂停。重开继续处理同一每日任务，不重复调用已经完成的故事阶段。空间设置明确提示重新开启可能处理积压的每日任务并产生API费用。

上述能力必须先部署新代码才存在，源码提交/推送不等于云端已更新。2026-10-27已推main的40cf56a，但10月28日公开检查仍是旧三张模式（当时136张照片/45个等待批次），没有部署管理入口，不能声称线上开关已改好。沿用持久化挂载，以保留网站开关、密钥和照片。

本次只补网站自动生成开关；“分批读完全天每张照片→统一汇总”和“补生成10月27日”仍是后续方案，当前代码仍最多选18张参考图，不可宣称已完成全量读图改造。

## 验证

- `npm run check`
- `npm test`：包含北京时间边界、跨年、默认不按三张生成、每日唯一、重启/晚到保护、迁移、参数校验、掉盘回滚、缺失源目录仍调度及8格模拟生成闭环。
- `npm run verify:daily`：隔离浏览器，设置保存、只读预览、禁用worker提示、中英文/手机布局；不调用付费API。
- `npm run verify:server`：登录开关、设备鉴权、持久化、心跳DOM稳定和实时作品状态。
- 本机无Docker Engine，未执行容器构建验收。`scripts/verify-container.mjs`已更新为三张不立即生成的默认行为，须运维构建后运行。

历史 `scripts/verify.mjs` / `scripts/verify-auto.mjs` 保留用于早期三张原型的参考，不再作为每日模式验收入口。
